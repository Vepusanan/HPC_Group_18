1. Experiment Overview & Conway's Cellular Automaton

Evaluating execution throughput, algorithmic scalability, and hardware efficiency of a 2D cellular automaton across CPU and GPU architectures.

Conway's Four Rules of Life

The grid is a 2D lattice where every cell $(r, c)$ is either Dead (0) or Alive (1). The state of each cell transitions synchronously per generation based on its 8 Moore neighbours:

1
Underpopulation: A live cell with < 2 live neighbours dies.
2
Survival: A live cell with 2 or 3 live neighbours stays alive.
3
Overpopulation: A live cell with > 3 live neighbours dies.
4
Reproduction: A dead cell with exactly 3 live neighbours becomes alive.

Experimental Methodology & Constraints

  • Zero Boundary Condition: Cells outside the $N \times N$ domain are strictly dead (zero boundary, no wrap-around toroidal distortion).
  • Identical Deterministic Initial State: Both CPU and CUDA versions initialize memory using the identical PRNG (Linear Congruential Generator, Seed 42).
  • Double Buffering ($O(1)$ Pointer Swapping): Two buffers (currentGrid and nextGrid) prevent race conditions and eliminate memory copies across 100 generations.
  • Consistent Hardware Environment: Executed in Google Colab with an NVIDIA Tesla T4 GPU (2,560 CUDA cores) and an Intel Xeon CPU to eliminate cross-machine hardware bias.

3. CPU vs CUDA Execution Architecture

Visualizing the fundamental architectural contrast: Latency-oriented sequential CPU core execution versus Throughput-oriented massive GPU thread parallelism.

Sequential CPU Architecture

Latency-Optimized Core
Outer Loop: row = 0 ... N-1
↓
Inner Loop: col = 0 ... N-1
↓
8 Neighbor Reads: (row+dr)*N + (col+dc)
↓
Single Cell Evaluated Sequentially
  • Execution Model: 1-2 powerful CPU cores process cells serially inside nested loops.
  • Memory Traversal: Contiguous row-major storage maximizes spatial L1/L2 cache prefetching, but instruction pipeline still handles 1 cell at a time.
  • Total Operations: For $4096 \times 4096$, CPU executes $16.78 \times 10^6 \times 100 \approx 1.68 \text{ billion}$ stencil updates serially, taking ~6.85 seconds.

Massive CUDA GPU Architecture

Throughput-Optimized SMs
Grid Launch: dim3 gridSize((N+15)/16, (N+15)/16)
↓
Thread Blocks: dim3 blockSize(16, 16) (256 threads)
↓
8 Warps per Block (32 threads coalesced across columns)
↓
Thousands of Cells Computed Simultaneously
  • Execution Model: 1 CUDA thread is dedicated to computing exactly 1 cell $(r, c)$.
  • Memory Coalescing: threadIdx.x indexes adjacent columns; global DRAM reads form unified 128-byte bus transactions.
  • Zero-Copy Pointer Swapping: Grids reside in GPU VRAM across all 100 iterations. Only $O(1)$ device pointers swap on host.

7. Technical Characteristics Comparison Matrix

Direct comparison of architectural and implementation trade-offs between Sequential CPU and CUDA GPU paradigms.

Characteristic Area CPU Implementation (2D Contiguous Array) CUDA GPU Implementation (2D Thread Blocks)
Execution Model Sequential execution via nested loops; 1 cell evaluated at a time per CPU core instruction pipeline. Massive thread parallelism; thousands of lightweight threads execute concurrently across GPU Streaming Multiprocessors.
Parallelism Level Limited / Serial baseline (1 hardware thread; instruction-level prefetching). Massive (256 threads per block, up to 65,536 concurrent thread blocks for 4096×4096).
Memory Hierarchy System DRAM with automatic L1/L2/L3 hardware caching; row-major contiguous allocation enables cacheline streaming. GPU GDDR6 Global VRAM (300 GB/s) + L1/L2 hardware cache + optional on-chip Shared Memory tile (SRAM).
Memory Optimization Pointer swapping (std::swap) between currentGrid and nextGrid avoids copying $N^2$ elements per generation. Coalesced 128-byte global memory transactions across warps + zero-copy pointer swapping on host across 100 generations.
Algorithmic Complexity $O(N^2 \times \text{iterations})$ time complexity, bound by serial clock cycles and DRAM latency. $O(\frac{N^2}{P} \times \text{iterations})$ where $P \gg 1000$ active threads hide memory latency through fast warp context switching.
Implementation Complexity Lower; straightforward nested C++ loops, standard pointers, no device synchronization or PCIe transfers. Higher; requires device memory management, warp coalescing considerations, boundary guard conditions, and kernel launch configuration.
Hardware Scalability Poor scalability as $N$ grows ($O(N^2)$ serial penalty; 4096×4096 takes over 6.8 seconds). Exceptional scalability; larger grids provide sufficient workload to saturate all SMs and hide memory access latency.
Ideal Workload Domain Small grids ($N \le 128$), single-generation step-debugging, or environments without discrete GPU hardware. Large-scale simulations ($N \ge 1024$), high generation counts, and compute-dense spatial lattice calculations.
